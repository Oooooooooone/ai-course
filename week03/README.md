한국어와 영어의 토큰화 비교 (Qwen3-8B 토크나이저 사용)

| 문장 | 한국어 토큰 수 | 영어 토큰 수 | 비율 |
|------|--------------|------------|------|
| 나는 어제 친구와 함께 영화를 봤다 | 15 | 8 | 1.88 |
| 인공지능은 데이터에서 규칙을 스스로 배운다 | 14 | 9 | 1.56 |

- 영어는 단어 하나가 토큰 하나인 경우가 많은데, 한국어는 음절 단위로 잘게 쪼개진다.

- 신조어("갓생", "힙하고")나 흔한 외래어("아메리카노")도 한국어 쪽이 더 많은 토큰을 쓴다.

## 직접 해보기 7 — 다음 토큰 확률

| 질문 | 1위 후보 확률 |
|------|--------------|
| 대한민국의 수도는? (한 단어로만) | '서울' 100.0% |
| 1+1=? (숫자만) | '2' 100.0% |
| 점심 메뉴 하나만 추천해줘 | '돈' 89.1% |
| 영어 이름 하나만 지어줘 | 'Oliver' 38.9%, 'Liam' 36.5%, 'Noah' 17.2% |
| 대한민국의 수도는? (지시문 없음) | '대한' 100.0% |
| 오늘 저녁 메뉴 하나만 추천해줘 | '삼' 99.9% |
| 내 이름의 뜻은? | '모' 39.0%, '길' 39.0%, '미' 12.7% |

- 지시문을 빼니 첫 토큰이 "서울"에서 "대한"으로 바뀌었다. 질문에 바로 답하지 않고 문장을 이어서 완성하려는 쪽으로 목표 자체가 바뀐 것이다.
- "저녁 메뉴"처럼 훈련 데이터에서 흔했던 문맥은 확률이 한 곳(삼겹살)에 극단적으로 쏠린다.
- "내 이름의 뜻은?"처럼 정답이 없는 질문은 확률이 여러 후보로 퍼진다. "모른다"에 해당하는 토큰은 상위에 올라오지 않는다.

## 직접 해보기 8 — 환각, 컷오프, 온도

### 환각

- 존재하지 않는 논문 질문(qwen3:8b): 지어낸 내용을 그대로 사실처럼 설명함
- 존재하지 않는 파이썬 함수 질문(qwen3:8b): "존재하지 않는다"고 인지는 했지만 이어서 사용법을 지어냄
- 같은 두 질문(gemma4 26B): 논문은 "확인되지 않는다"며 정보를 더 요청, 함수도 "존재하지 않는다"를 먼저 밝히고 나서 대안 제시

### 지식 컷오프 (실제: 2024년 노벨 물리학상 = 존 홉필드, 제프리 힌턴)

- qwen3:8b: 존재하지 않는 이름을 지어내 오답
- gemma4(26B): 정확히 맞힘. 2025년 질문에는 "내 지식 컷오프는 2025년 1월까지"라고 스스로 밝힘

### 온도

- temperature=0: 두 모델 다 세 번 모두 완전히 동일한 문장
- temperature=1.5: qwen3:8b는 세 번 다 표현이 크게 다름, gemma4는 표현이 비슷하게 유지되며 미세하게만 달라짐

## 직접 해보기 10 — 틀린 답을 우겨서 동조 확인

| 질문 | 원래 답 | 우긴 뒤 답 |
|------|---------|-----------|
| 가장 높은 산 | 에베레스트 (정답) | 그대로 유지 |
| 물의 끓는점 | 100 (정답) | 90으로 굴복 |

압도적으로 확고한 상식(에베레스트)은 우겨도 안 바뀌지만, 계산이나 덜 확고한 사실은 사용자가 틀린 답을 우기면 쉽게 굴복한다.

## 직접 해보기 12 — 대화 기억 확인

| 상황 | 결과 |
|------|------|
| "내 이름은 최민수야, 기억해 줘" | "알겠어, 최민수." |
| 이전 대화 없이 "내 이름이 뭐라고 했지?" | "당신의 이름은 알려드릴 수 없습니다." |
| 이전 대화 포함해서 같은 질문 | "최민수야." |

모델 자체는 아무것도 저장하지 않는다. 이전 대화를 매 요청마다 통째로 다시 보내주기 때문에 기억하는 것처럼 보이는 것뿐이다. 대화가 길어질수록 보내는 양이 계속 늘어나고, 이게 앞서 본 컨텍스트 상한 문제로 이어진다.
